# Kafka 토픽 설정과 Connect 커넥터 관리

## 원인과 변경
- 기존 토픽 상세 화면은 브로커에서 설정을 읽기만 했다. 설정 탭에서 개별 값을 변경하고 토픽 오버라이드를 삭제할 수 있게 했다. 삭제는 토픽·레코드 삭제가 아니며 브로커 또는 Kafka 기본값을 다시 상속한다. Kafka의 증분 설정 API를 사용하므로 다른 키는 건드리지 않는다.
- 기존 Connect 화면은 상태와 설정만 표시했다. 현재 프로필의 Connect REST로 새 커넥터 등록, 재시작, 삭제를 요청하고 결과를 다시 조회한다. 등록은 `POST /connectors`를 사용하므로 같은 이름의 기존 설정을 덮어쓰지 않는다.
- 토픽 변경·초기화 및 커넥터 삭제·재시작은 대상을 보여 준 뒤 확인받는다. 연결 프로필이 바뀌면 이전 화면의 변경 요청을 거부한다. Connect 쓰기 응답에서 백엔드가 보낸 원문은 비밀 설정 노출을 막기 위해 반환하지 않는다.

## 사용
- **토픽 → 토픽 이름 → 설정:** 키의 **변경** 또는 **오버라이드 삭제**를 선택한다. 브로커가 읽기 전용으로 표시한 설정은 편집할 수 없다.
- **Connect → 커넥터 등록:** JSON 파일을 불러오거나 편집기에 직접 입력한다. 최대 크기는 1 MiB다. `{"name":"example","config":{"connector.class":"…","tasks.max":"1"}}` 형식 또는 `{"name":"example","connector.class":"…","tasks.max":"1"}` 형식을 사용할 수 있다. 실제 클래스와 나머지 설정은 해당 Connect 워커의 플러그인에 맞춘다.
- **Connect → 커넥터 → 재시작 / 삭제:** 재시작은 요청 접수를 뜻한다. 실제 상태는 목록에서 확인한다. Kafka Connect 3.0 이상에서 커넥터의 태스크까지 재시작을 요청한다.

## 검증
- `go test ./...` 및 Windows `-tags production` 빌드.
- `.tools/.test/management.test.mjs`: 로컬 kfake, 모의 Connect REST, 실제 콘솔 HTTP 서버에서 요청을 실행한다. 단일 키 변경·원복, 다른 키 보존, 입력 오류·대상 변경 거부, 중복 등록, 민감값 비노출, 리다이렉트 미추종, 재시작과 삭제를 검증한다.
- 재현: `.tools/.build/kfake`와 `./app`을 각각 Go로 빌드하고 실행 파일 경로를 `KVC_TEST_KAFKA`와 `KVC_TEST_CONSOLE`에 지정한다. `node --test .tools/.test/management.test.mjs`를 실행한다. `KVC_TEST_PLAYWRIGHT`에 Playwright 모듈의 `index.mjs` 절대 경로를 지정하면 Edge 브라우저에서도 토픽 변경·원복, 직접 입력·파일 등록, 재시작·삭제 확인·취소를 검증한다.

## 운영 주의
- 운영 Kafka·Kafka Connect에는 쓰기 요청을 하지 않았다. 실제 적용에는 브로커의 설정 변경 권한과 Connect REST의 관리 권한이 필요하다.
- Kafka 토픽 변경에는 증분 설정 API를 지원하는 브로커(Kafka 2.3 이상)가 필요하다. 보존 기간 등 일부 설정 변경은 데이터에 영향을 줄 수 있다.
- HTTP 모드는 자체 사용자 인증이 없다. `-listen 127.0.0.1:8080` 사용을 권장한다. 원격으로 제공하려면 인증과 접근 제어를 별도로 적용해야 한다.
